# Audit of the agent starter kit — 2026-09-28

Naming note: this audit was written before publication. It calls the pre-publication draft "kit v1.0"
and the revised kit "v2.0". At publication the labels were swapped: the revised kit was released as
**v1.0** and the draft is "the unreleased draft". The file edits in §6 were applied to the repository
in the same session; the PRD in §7 is `PRD.md` at the repository root.

Method: six phases (read and map; scientific research only; vendor documentation only; repository
survey; synthesis and edits; PRD), each closed by a verification gate that re-opened every URL cited
and checked every quoted sentence and number. Gate totals across all phases: **VERIFIED 344 ·
MISMATCH 3 · NOT FOUND 10**; every mismatch was dropped or corrected before use.

## 3. Rejections re-examined

| Rejection | What the sources say | Verdict |
|---|---|---|
| **justfile** | No scientific work on task runners (arXiv search: none). Strong evidence that the harness and an executable check move outcomes: "agents with identical underlying models differ substantially, suggesting scaffolding is as important as the model" (2602.19594); harness changes alone shift quality across 35 releases (2607.03691); "Self-Debugging improves the baseline accuracy by up to 12%" with unit tests (2304.05128); TDD framework +9.49 pp (2509.24148). Practice: `justfile` absent from a sibling repository 21 days after being marked Core; `agents-with-receipts` checks for "one verification command". | **Rejection stands, reason corrected.** The kit lacked the entry point, not the tool: `ops/verify.sh` (no dependency) is required; `just` remains optional. |
| **Rule cap** | Harada et al. (Findings of EMNLP 2025): "performance consistently degrades as the number of instructions increases", 0.574 at 5, 0.213 at 10; CSE: "Reliable instruction following breaks down beyond 5-6 simultaneous constraints"; IFScale: earlier-instruction bias. Counter: McMillan finds no effect of file size, position or adjacent-file conflicts on single-instruction compliance — the collapse is in jointly binding constraints. | **Rejection was wrong.** Cap the binding rules at 7 (the number is a choice; the direction is peer-reviewed), rank them, enforce the count. |
| **docs/specs–plans–adr tree** | Plans: "Providing the standard plan improves issue resolution … A subpar plan hurts performance even more than no plan at all" (2604.12147); plan files in 10 of 36,710 repositories (ESEM 2026, 2608.04661). ADRs: LLMs detect violations with "strong accuracy for explicit, code-inferable decisions" (2602.07609) regardless of file form. Specs: requirement smells lower correctness (PROFES 2026, 2609.29208); ambiguity degrades and is not self-detected (2604.21505). | **Rejection stands.** Plans stay optional and disposable; decisions stay in one append-only file with explicit `Rejected:`; specs stay out of always-on context and precise when used. |
| Stop hook · Gemini settings entry | See §1 rows 2 and 5 | **Both reversed** |
| Symlinks, `.cursorrules`, copilot-instructions · `@path` includes · per-tool feature files · post-session auto-summary · hooks-only · one file per decision | Zed reads "the first matching file in this list"; only Claude, Gemini, Copilot CLI expand `@`; skills mostly static; SessionEnd is advisory everywhere; Devin/Zed have no hook; no evidence on decision-file form | **All stand** |

## 8. Still unproven (opinion, not evidence)

- That a status/handoff file improves outcomes at all (no study; nearest: 2609.23570).
- The numbers 7, 100, 60, 20, 40, 3, 300 s — direction evidenced, values chosen.
- End-of-session wrap-up compliance under prose alone (unmeasured).
- Whether gating on completion claims is tolerable in daily use.
- Gemini/Antigravity hook config shapes; Copilot CLI's handling of Claude-format hooks; Codex `apply_patch` input for file protection.
- Pointer files vs symlinks vs settings entries: no science; practice and vendor docs only.
- One-file vs one-folder decision logs: no science.
- `.env.example`, `justfile`: no science; practice only.
- Whether McMillan's file-structure null generalises beyond Claude Code on TypeScript (preprint, one harness).
- Whether an always-on learnings list of ≤ 20 lines nets positive against the +20 % cost of context (Gloaguen) — the 30-day metrics are the test.
